# Create a visual

1. Restate the visual goal in one sentence.
2. Choose a route by intent, not by subject.
3. Load shared references and the route references listed in `routing.yaml`.
4. List every element of the subject the reader would expect to find. Mark each one kept or cut, and say why in prose. For a diff or a pull request, take the list from `references/subject-inventory.md`.
5. When the visual shows code, a diff, or a plan that lives in a repo, read the real lines and tie every arrow to a `path:line` citation before drawing. When the picture and the source disagree, the picture is wrong.
6. Sketch the smallest useful structure before writing markup.
7. Keep labels short and put explanation in surrounding prose.
8. Build from the route template.
9. Run package and artifact validators.
10. Inspect the rendered result for clipping, overlap, legibility, and appearance-mode support.

Use an overview plus detail visuals when the content exceeds the route limits.
