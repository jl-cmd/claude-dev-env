Findings that prevent approval

Claude installer merge still loses a validator. Canonical hooks.json has two write groups with the same matcher. mergeHooksIntoSettings replaces the first managed group while processing the second. A narrow in-memory reproduction retained the dispatcher, dropped the inline validator, preserved a foreign hook and permissions, and repeated the same result. This was not a full installer run.

Codex is a separate deployment path. codex_compat_materializer.py adds an apply_patch code-rules hook, preserves other target hooks, and its inspected retired-hook set names only session/untracked_repo_detector.py. Claude's retired PR-hook list does not establish equivalent Codex pruning.

Native Git still invokes the older gate. pre_commit.py calls the shared staged CODE_RULES gate, not cde lint. pre_push.py still scopes the policy gate to checkout HEAD, including when another object is pushed. The installer still generates pre-commit and pre-push, so deleting their installed shims alone would not persist.

Policy lint is not the entire local toolchain. Its validator adapter explicitly uses include_ruff=False. Mypy has a separate blocking post-write hook. Terminology is staged-only. Stored-prompt lint does not inspect live AskUserQuestion payloads, and Python-file rmtree lint does not replace transient shell-command protection.

Retire registrations, not shared implementations. Policy-lint adapters import existing blocking modules, including code_rules_enforcer, state_description_blocker, windows_rmtree_blocker, and duplicate_rmtree_helper_blocker. Deleting those scripts would damage the replacement.

Legacy direct registrations need their own proof. The inspected Claude managed-path sets do not name retired test_preflight_check.py or es_exe_path_rewriter.py. Their absence from the current dispatcher does not prove every older standalone registration is pruned. Codex, alternate profiles, project settings, and Git overrides need independent readback.
